# Rust AutoConnect - AI Onboarding & Context

**Добро пожаловать в проект Rust AutoConnect!**
Этот файл содержит всю суть и архитектуру проекта. Обязательно прочитай его перед тем, как начинать работать с кодом.

## Суть проекта
**Rust AutoConnect** — это мощное десктопное приложение для игроков в игру Rust. Оно позволяет пользователям мониторить статус серверов, автоматически подключаться при появлении свободных слотов, получать уведомления в Telegram (о продвижении в очереди, смерти, начале игры), а также отправлять статистику и бенчмарки на глобальный лидерборд (через Supabase). Проект написан на Python с использованием `CustomTkinter` для современного и красивого UI.

## Важные файлы и модули

### 1. `src/app.py`
**Роль**: Сердце приложения (Контроллер). Наследует `MainWindow` из GUI и объединяет логику.
**Функции/Особенности**:
- Управляет глобальными состояниями: `self.is_polling`, `self.is_reconnecting`.
- Содержит фоновые циклы (`check_rust_status_loop`, `check_rust_update_loop`), которые мониторят запущен ли Rust, чтобы управлять логикой авто-реконнекта.
- Строго соблюдает границу между `threading` (обычные потоки) и UI. Все запросы на обновление интерфейса передаются в главный поток через функцию `self.dispatch_ui(callback)`.

### 2. `src/gui/` (Пользовательский интерфейс)
- **`main_window.py`**: Главный класс UI. Отрисовывает дашборд, кнопки подключения, историю серверов.
- В этой папке нет тяжелой логики, только отрисовка и биндинги на контроллер в `app.py`.

### 3. `src/services/` (Сервисы и Фоновые задачи)
- **`log_watcher.py` (LogWatcher)**: Очень важный асинхронный сервис. Он в реальном времени читает лог-файл Раста (`client.log`) и парсит события: какую позицию в очереди занимает игрок, когда игрок зашёл на сервер, когда умер. Эти события передаются через колбеки (`on_event`, `on_queue_update`).
- **`telegram_service.py` / `webhook_service.py`**: Отвечают за отправку уведомлений пользователю в Телеграм. Используют секретный код для привязки.
- **`process_monitor.py`**: Ищет процессы `RustClient.exe`. Отвечает за запуск игры через `steam://run/252490//+connect ...`.
- **`leaderboard_service.py`**: Сбор железа (WMI/psutil), парсинг результатов бенчмарка из логов Раста и безопасная отправка результатов на API Supabase.
- **`server_intelligence_service.py`**: Запросы к API для получения активного количества игроков и времени вайпа на сервере (Edge Functions Supabase).

### 4. `src/core/` (Ядро)
- **`a2s_client.py`**: Отвечает за прямые UDP-запросы к игровым серверам Rust по протоколу A2S (Source Engine Query). Позволяет быстро узнать онлайн, название сервера и максимальное количество игроков без запуска самой игры.
- **`smart_monitor.py`**: Машина состояний (State Machine), которая управляет логикой переподключения (ждет слот, коннектится, ждет загрузки).

## Критические архитектурные правила
1. **asyncio vs threading**: В проекте есть как потоки `threading`, так и корутины `asyncio` (например, в парсере логов). **Крайне осторожно** вызывай `async` методы из обычных потоков — обязательно используй безопасные обертки вроде `asyncio.run_coroutine_threadsafe(coro, self.async_loop)`. Если забыть, программа упадет с ошибкой `RuntimeError: no running event loop`.
2. **Безопасность UI**: Никогда не обновляй `CustomTkinter` элементы (кнопки, лейблы, окна `messagebox`) напрямую из фоновых потоков (из бенчмарка, из сетевого мониторинга). Всегда оборачивай это в `self.dispatch_ui(...)`.
3. **Хранение секретов**: Ключи Supabase подтягиваются динамически. Не хардкодь их. Телеграм токены тоже хранятся в защищенных файлах или ENV.

## Как работать с обновлениями
Если пользователь просит добавить фичу или пофиксить баг, после выполнения задачи:
1. Запиши изменения в файл `CHANGELOG.md` в корне проекта (Локально).
2. Закоммить изменения (`git commit -m "..."`).
3. Никогда не делай `git push` в GitHub! Только локальные коммиты, пока пользователь не прикажет обратное.
